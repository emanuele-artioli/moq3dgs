# MOQ3DGS — Claude Code

@.claude/project-core.md

`AGENTS.md` at the repo root is this project's real, hand-edited rule set, read
directly by Cursor, Antigravity, Codex and Copilot's cloud agent. Claude is the
one agent that will not look at it, so this file imports a generated slice
instead: **`.claude/project-core.md` is `AGENTS.md` minus two things a Claude
session already has elsewhere** — the `host-rules` block (loaded from
`~/.claude/CLAUDE.md`) and every section marked `<!-- scope: ... -->`, which
arrives on its own from `.claude/rules/` the moment a file it covers is read.

Add nothing here that is not specific to Claude Code: project rules belong in
`AGENTS.md`, host-wide rules in `~/.agent-rules/AGENTS.md`. Everything under
`.claude/project-core.md`, `.claude/rules/` and `.github/instructions/` is
generated by `tools/sync_agent_rules.py` — edit `AGENTS.md` and re-run it.

## Claude-specific notes

- **The deferred sections are listed at the end of `.claude/project-core.md`.**
  They load automatically when you open a matching file. If you are reasoning
  about one of those areas *without* opening its files — planning an
  experiment, answering a question about the test suite — read the matching
  file under `.claude/rules/` first rather than assuming you have the rules.
- Hooks for this project are wired in `.claude/settings.json`: repo state at
  session start and the `rm` guard before every `Bash` call. They call the
  shared scripts in `~/.agent-rules/scripts/`; the values they enforce come
  from `.agent-guards.json` in this repo.
- Sessions spawned with `spawn_task` chips get their own worktree under
  `.claude/worktrees/`. Sessions started any other way share this checkout's
  HEAD — see the concurrency rules in `AGENTS.md` before running two at once.
